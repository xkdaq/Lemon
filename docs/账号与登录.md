# 账号与登录

## 核心规则

- **手机号是唯一身份**：一个手机号只对应一个账号（`app_user.phone` 唯一）。
- **用户名**自动分配（`lemon` + 数字，以字母开头，和手机号区分），**不可修改**；昵称可以随时改。
- 密码、用户名、微信 openid 都只是这个账号的登录方式，不是独立账号。所以 Web 端和小程序端的同一个人天然是同一个账号，
  做题进度、错题、收藏两端互通，**不需要做账号合并**。
- **主推账号密码登录**，短信只在「注册」和「忘记密码」时发，省短信费。
- 小程序是个人主体，不能授权手机号；首次用账号密码（或短信注册）登录时绑定微信，以后静默登录。所以每个账号仍然都有手机号。

相关字段：`username` 用户名；`phone_verified` 手机号是否验证过（短信或小程序手机号快速验证）；
`must_change_password` 后台重置过密码、登录后要提示修改。

## Web 端（已实现）

| 功能 | 接口 | 说明 |
|---|---|---|
| 发验证码 | `POST /api/app/auth/sms-code` `{phone, purpose}` | `purpose = register`：手机号已注册就不发；`reset`：没注册就不发 |
| 注册 | `POST /api/app/auth/register` `{phone, code, password, nickname?}` | 验证码 + 设置密码一步完成，自动分配用户名，注册后自动登录 |
| 登录 | `POST /api/app/auth/login` `{account, password}` | `account` 是手机号或用户名（不区分大小写） |
| 忘记密码 | `POST /api/app/auth/reset-password` `{phone, code, password}` | 重置后自动登录，其他设备全部下线 |
| 修改 / 设置密码 | `POST /api/app/user/password` `{oldPassword?, password}` | 需登录；已有密码要验证原密码，还没密码的（小程序用户）直接设置；其他设备下线 |
| 修改昵称 | `PUT /api/app/user/nickname` `{nickname}` | 需登录 |

后台「用户管理」可以**重置密码**：生成 8 位临时密码（只显示一次，由管理员转告用户），所有设备下线；
用户用临时密码登录后会被要求修改密码。

短信：Spug 推送助手「短信验证码」官方模板，服务器环境变量 `SMS_SPUG_URL` 填完整调用 URL（`https://push.spug.cc/sms/...`），
模板带有效时长时 `SMS_SPUG_MINUTES=5`。开发环境不配置时验证码打印在后端日志里。每次实际发送记录在 `sms_log`，后台「短信记录」可查。

限流：同一手机号 60 秒 1 次、每天 10 次；同一 IP 每小时 20 次；验证码 5 分钟有效、用过即失效、最多试错 5 次。
如果发现被刷短信（短信记录里同一 IP 大量请求、很多从没注册成功的手机号），再加图形验证码 / 滑块。

### 早期"抢注"账号的处理

上线初期「手机号 + 密码」注册时没有验证手机号（这些账号 `phone_verified = 0`），理论上 A 可以用 B 的手机号注册。
真正的机主用「忘记密码」（短信验证手机号）重置密码后，账号就归他：密码被替换，其他设备上的登录全部下线。

## 小程序端（已实现，个人主体）

小程序是**个人主体**。微信的「手机号快速验证 / 实时验证」只对完成认证的非个人主体开放
（[官方文档](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/getPhoneNumber.html)），
所以小程序**不能授权手机号登录**，改为「首次用账号登录时绑定微信，以后静默登录」：

1. **首次**：小程序登录页和网页一样，账号（手机号或用户名）+ 密码登录，或短信注册 / 找回密码。
   请求里带上 `wx.login()` 的 `code`（参数 `wxCode`，三个接口都支持，可选），登录成功后后端调 `jscode2session`
   换 `openid`（和 `unionid`，如果小程序绑定了开放平台），绑到这个账号上。绑定失败不影响这次登录。
   小程序里短信注册的账号 `register_from` 仍是 1（和 Web 注册走同一个接口）。
2. **以后**：静默登录 `POST /api/app/auth/wx-silent-login` `{code}`，openid 绑过账号就直接登录，没绑过返回 `token = null`。
   启动时、以及任何接口返回 401 时都会先试一次静默登录，成功后重发原请求。
3. 用户在小程序里主动「退出登录」后，本机不再静默登录，直到他再次手动登录。

开发环境（`dev` profile）没配 `WX_APPID` 时走模拟登录：所有 `code` 都当成同一个微信（openid = `mock-devtools`，和真实情况一样同一个微信 openid 固定）；
接口测试要模拟不同的微信时传 `code = "mock:<任意标识>"`（openid = `mock-<标识>`）。生产环境不会模拟。

### 边界情况

| 情况 | 处理 |
|---|---|
| 这个微信已经绑在别的账号上，用户又用另一个账号登录 | 以最后一次登录为准，改绑到新账号（输对了密码 / 验证了手机号，能证明账号是他的），旧账号下次要手动登录 |
| 账号已经绑了另一个微信（换了微信号） | 换成新的 openid，旧微信号不能再静默登录 |
| 网页用户想用小程序 | 在小程序用原来的手机号或用户名 + 密码登录一次即可，做题记录互通 |
| 小程序用户想用网页 | 小程序里注册的账号本来就有密码，直接在网页登录 |
| 密码登错 | 不绑定 |

### 备用：企业主体的手机号快捷登录（后端已实现，前端未启用）

以后换成**已认证的企业主体**，可以启用 `POST /api/app/auth/wx-login`（`code` + `phoneCode`）：用 `<button open-type="getPhoneNumber">`
拿 `phoneCode`，后端换手机号后按手机号找账号——有就绑定 openid（手机号没验证过的账号旧密码作废、其他设备下线），没有就新建（没有密码）；
这个微信已绑在别的手机号账号上时提示"该微信已绑定手机号 1xx****xxxx"。按次收费 0.03 元（每个小程序有 1000 次体验额度）。

### 准备工作

- 小程序 AppID / AppSecret：服务器 `deploy/.env` 里填 `WX_APPID` / `WX_SECRET`（不进代码仓库），`lemon-app/src/manifest.json` 的 `mp-weixin.appid` 填 AppID。
- 小程序后台把 API 域名（`api.` 子域名）配置为 request / uploadFile / downloadFile 合法域名。
- 小程序后台填写《用户隐私保护指引》，声明：相册（笔记选图片）、剪切板（复制解析 / 微信号）。没声明的接口会被直接禁用；
  首次调用时微信会自动弹官方隐私授权框，不用自己开发。
