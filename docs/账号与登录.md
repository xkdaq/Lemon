# 账号与登录

## 核心规则：手机号是唯一身份

- 一个手机号只对应一个账号（`app_user.phone` 唯一）。
- 密码、微信 openid 都只是**这个账号的登录方式**，不是独立账号。
- 所以 Web 端和小程序端的同一个人天然是同一个账号，做题进度、错题、收藏两端互通，**不需要做账号合并**。
- 小程序**必须授权手机号**才能登录（不提供"只用微信登录"），保证每个账号都有手机号。

`app_user.phone_verified` 表示手机号是否被验证过（短信验证码，或小程序手机号快速验证）。

## Web 端（已实现）

| 方式 | 接口 | 说明 |
|---|---|---|
| 验证码登录 | `POST /api/app/auth/sms-code` → `POST /api/app/auth/sms-login` | 没注册过自动注册；登录后 `phone_verified = 1` |
| 密码登录 | `POST /api/app/auth/login` | 只有设置过密码的账号能用 |
| 设置 / 修改密码 | `POST /api/app/user/password/code` → `POST /api/app/user/password` | 需登录；验证码发到账号自己的手机号，也算验证了手机号 |

短信：Spug 推送助手「短信验证码」官方模板，服务器环境变量 `SMS_SPUG_URL` 填完整调用 URL（`https://push.spug.cc/sms/...`），
选了带有效时长的模板时 `SMS_SPUG_MINUTES=5`。不配置时验证码登录不可用；开发环境不配置时验证码打印在后端日志里。

限流：同一手机号 60 秒 1 次、每天 10 次；同一 IP 每小时 20 次；验证码 5 分钟有效、用过即失效、最多试错 5 次。

### 早期"抢注"账号的处理

上线初期是「手机号 + 密码」注册，没有验证手机号（这些账号 `phone_verified = 0`），理论上 A 可以用 B 的手机号注册。
处理规则：**谁先验证了手机号，账号就归谁**。未验证的账号第一次通过验证码（或小程序手机号快速验证）验证时：

1. `phone_verified` 置 1；
2. 如果设置过密码，旧密码作废，其他设备上的登录全部下线（当前操作的设备除外）；
3. 前端提示"之前设置的密码已失效，可在设置里重新设置"。

## 小程序端（二期，待实现）

登录流程（`POST /api/app/auth/wx-login`，参数 `code` + `phoneCode`）：

1. 前端 `wx.login()` 拿 `code`，后端调 `jscode2session` 换 `openid`（和 `unionid`，如果小程序绑定了开放平台）。
2. 前端用 `<button open-type="getPhoneNumber">` 手机号快速验证拿 `phoneCode`，后端调 `getuserphonenumber` 换手机号。
   这个手机号由微信验证过，等同于短信验证。
3. 按手机号找账号：
   - **有账号**（包括 Web 注册的）：按上面"抢注"规则标记 `phone_verified`，把 `openid` 绑到这个账号上；
   - **没有账号**：新建账号，`phone` + `openid` 一起写入，`register_from = 2`，`phone_verified = 1`。
4. 登录这个账号，返回 token。

以后再进小程序：先用 `wx.login` 的 openid 找账号，找到就直接登录（静默登录），不用每次授权手机号。

### 边界情况

| 情况 | 处理 |
|---|---|
| 账号已经绑了另一个 openid（换了微信号） | 以手机号为准，换成新的 openid（旧微信号不能再静默登录） |
| 这个 openid 已经绑在别的手机号账号上（同一个微信号换了手机号授权） | 提示"该微信已绑定手机号 1xx****xxxx"，不自动改绑，避免一个微信号来回串账号 |
| Web 端用户想用小程序 | 直接在小程序授权同一个手机号，自动进入同一个账号 |
| 小程序用户想用 Web 端 | Web 端用同一个手机号验证码登录即可；想用密码登录先在「设置」里设置密码 |
| 用户换了手机号 | 二期再做"更换手机号"（新旧号码都要验证），目前不支持 |

### 准备工作

- 小程序 AppID / AppSecret（服务器环境变量，不进代码仓库），`manifest.json` 里填 AppID。
- 手机号快速验证组件按次收费，需在小程序后台开通并充值。
- 小程序后台把 API 域名配置为 request 合法域名。
