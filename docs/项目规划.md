# 刷题小程序（Lemon）整体规划

## 1. 项目概述

面向考研（政治 / 教育学 311）的刷题产品。**一期先上 Web 端（H5，PC + 手机浏览器都能用），小程序二期再发**，网站和小程序的备案同步申请。

| 子系统 | 用户 | 技术栈（建议） | 期次 |
|---|---|---|---|
| 用户端 `lemon-app` | 考生 | uni-app（Vue3 + TS），**一期编译为 H5 发布 Web**，二期同一套代码编译微信小程序 | 一期 H5 / 二期小程序 |
| 后台接口 `lemon-server` | 用户端 + 管理系统 | Java 17 + Spring Boot 4.1 + MyBatis-Plus 3.5 + MySQL 8 + Redis 7 | 一期 |
| 管理系统 `lemon-admin` | 运营 / 录题人员 | Vue3 + Vite + Element Plus + Pinia | 一期 |

> 后端一个 Spring Boot 工程，按路由前缀拆成两套接口：`/api/app/**`（用户端，JWT）和 `/api/admin/**`（后台，账号密码 + RBAC）。初期单体部署即可，没必要上微服务。
>
> **为什么用户端选 uni-app 而不是纯 Vue Web**：Web 先上、小程序后上，用 uni-app 写一套页面，`npm run build:h5` 出网站，`build:mp-weixin` 出小程序，二期基本只需适配登录和少量 API 差异，不用重写。代价是 PC 大屏体验要做响应式适配（内容区限宽居中即可，刷题场景足够）。

### 1.1 Web 端与小程序的差异处理

| 点 | Web（一期） | 小程序（二期） | 处理方式 |
|---|---|---|---|
| 登录 | 手机号 / 用户名 + 密码（注册和忘记密码时发短信验证码） | 微信 `wx.login` + 手机号快速验证（必须授权手机号），直接登录 | 手机号是唯一身份，openid 绑在手机号账号上，两端是同一个账号，详见 [账号与登录](账号与登录.md) |
| 存储 / 跳转 | localStorage、vue-router | wx.storage、页面栈 | uni-app API 已抹平 |
| 分享 | 复制链接 | 小程序卡片分享 | 条件编译 `#ifdef` |
| 布局 | 需兼容 PC 宽屏 | 只有手机 | 内容区 `max-width: 750px` 居中，PC 端侧边留白 |

## 2. 内容层级模型（核心）

需求里有两处都叫“科目”，为避免混淆，统一命名：

- **模块（module）**：首页的大入口，即「政治」「教育学」
- **题库（bank）**：模块下由后台新建，分两种类型
- **科目（course）**：题库下的子科目，如「马原」「毛中特」
- **章节（chapter）**：题目的直接归属单位
- **题目（question）**

```
模块 政治
├── 题库 A【科目型 type=1】  例：政治基础题库
│   ├── 科目 马原
│   │   ├── 章节 第一章 世界的物质性 → 题目…
│   │   └── 章节 第二章 …
│   └── 科目 毛中特
│       └── 章节 …
└── 题库 B【试卷型 type=2】  例：2026 冲刺模拟卷
    ├── 章节 模拟卷（一）→ 题目…
    └── 章节 模拟卷（二）→ 题目…

模块 教育学
└── 同上结构（科目可为：教育学原理 / 中外教育史 / 教育心理学 / 教育研究方法）
```

**设计要点**：章节表同时带 `bank_id` 和可空的 `course_id`。

- 科目型题库：章节 `course_id` 必填
- 试卷型题库：章节 `course_id` 为空，章节即“一套卷”，可额外配置 `time_limit`（考试时长）、`total_score`

这样题目只挂章节一个外键，两种题库共用同一套做题、收藏、错题逻辑。

## 3. 功能清单

### 3.1 用户端（一期 Web，二期小程序，页面一致）

| 页面 | 功能 |
|---|---|
| 登录 / 注册 | 手机号 + 短信验证码登录（未注册自动注册）；短信签名未下来前用手机号 + 密码注册登录 |
| 首页 | 两个模块卡片（政治 / 教育学）、Banner、公告、“继续上次练习”入口、今日做题数 |
| 题库列表 | 进入模块后展示题库列表，标识类型（章节练习 / 模拟卷）和进度 |
| 科目列表 | 科目型题库进入后显示科目（马原、毛中特…），带完成度 |
| 章节列表 | 章节名、题量、已做 / 正确率；试卷型直接显示卷子列表 |
| 做题页 | 见下方“做题模式”；支持左右滑动切题、答题卡、收藏、查看解析、字号调节、夜间模式 |
| 结果页 | 本次正确率、用时、错题回顾；模拟卷出分数 |
| 收藏集 | 按模块 → 题库 → 章节分组；可在收藏集内直接刷题；支持取消收藏 |
| 错题集 | 按模块 / 科目分组，显示错误次数；“错题重练”；答对 N 次自动移出（N 后台可配，默认 2）；可手动移出 |
| 我的 | 头像昵称（Web 自行上传，小程序取微信资料）、做题统计（总题数 / 正确率 / 连续打卡天数）、意见反馈、设置 |

**做题模式**

| 模式 | 适用 | 说明 |
|---|---|---|
| 练习模式 | 章节 | 选完即判题，显示解析，错题自动进错题集 |
| 背题模式 | 章节 | 直接显示答案和解析，不计入统计 |
| 考试模式 | 模拟卷 | 计时、交卷后统一判分，可中途保存，倒计时到点自动交卷 |

**题型支持**（覆盖政治和 311）

| 题型 code | 名称 | 判题 |
|---|---|---|
| 1 | 单选题 | 自动 |
| 2 | 多选题 | 自动（全对才算对） |
| 3 | 判断题 / 辨析题客观部分 | 自动 |
| 4 | 主观题（分析 / 简答 / 论述 / 辨析） | 展示参考答案 + 得分点，用户自评“会 / 不会”，“不会”进错题集 |

### 3.2 管理系统

| 菜单 | 功能 |
|---|---|
| 工作台 | 用户数、日活、今日答题数、题库题量统计、新增趋势图 |
| 模块管理 | 政治 / 教育学的名称、图标、排序、上下架（预留扩展新模块） |
| 题库管理 | 新建题库时选类型（科目型 / 试卷型）、封面、简介、排序、上下架、是否免费（预留付费） |

| 章节管理 | 树形展示（题库 → 科目 → 章节）；试卷型可设考试时长、总分 |
| 题目管理 | 按题库 / 科目 / 章节 / 题型 / 关键字筛选；富文本编辑题干、选项、解析（支持图片）；批量移动、批量删除、上下架 |

| 反馈管理 | 用户题目纠错 / 意见反馈处理 |
| 运营配置 | Banner、公告、错题移出阈值等系统参数 |
| 系统管理 | 管理员账号、角色、菜单权限（RBAC）、操作日志 |

## 4. 数据库设计（MySQL 8，utf8mb4）

通用字段：`id BIGINT 主键`、`created_at`、`updated_at`、`deleted TINYINT`（逻辑删除）。下文省略。

### 4.1 内容域

```sql
-- 模块（政治 / 教育学）
CREATE TABLE module (
  name        VARCHAR(32)  NOT NULL,
  icon        VARCHAR(255),
  sort        INT DEFAULT 0,
  status      TINYINT DEFAULT 1           -- 1 上架 0 下架
);

-- 题库
CREATE TABLE question_bank (
  module_id   BIGINT NOT NULL,
  name        VARCHAR(64) NOT NULL,
  type        TINYINT NOT NULL,           -- 1 科目型 2 试卷型
  cover       VARCHAR(255),
  intro       VARCHAR(500),
  sort        INT DEFAULT 0,
  status      TINYINT DEFAULT 1,
  question_count INT DEFAULT 0,           -- 冗余题量，便于列表展示
  INDEX idx_module (module_id, status, sort)
);

-- 科目（仅科目型题库）
CREATE TABLE course (
  bank_id     BIGINT NOT NULL,
  name        VARCHAR(64) NOT NULL,
  sort        INT DEFAULT 0,
  status      TINYINT DEFAULT 1,
  INDEX idx_bank (bank_id, sort)
);

-- 章节（试卷型题库的一章 = 一套卷）
CREATE TABLE chapter (
  bank_id     BIGINT NOT NULL,
  course_id   BIGINT NULL,                -- 试卷型为 NULL
  name        VARCHAR(128) NOT NULL,
  sort        INT DEFAULT 0,
  status      TINYINT DEFAULT 1,
  time_limit  INT NULL,                   -- 试卷型：考试分钟数
  total_score INT NULL,
  question_count INT DEFAULT 0,
  INDEX idx_bank_course (bank_id, course_id, sort)
);

-- 题目
CREATE TABLE question (
  chapter_id  BIGINT NOT NULL,
  bank_id     BIGINT NOT NULL,            -- 冗余，方便统计 / 筛选
  module_id   BIGINT NOT NULL,            -- 冗余
  type        TINYINT NOT NULL,           -- 1 单选 2 多选 3 判断 4 主观
  stem        TEXT NOT NULL,              -- 题干（富文本）
  options     JSON,                       -- [{"key":"A","content":"..."}]
  answer      VARCHAR(500),               -- 客观题："A" / "ABD"；主观题放 analysis
  analysis    TEXT,                       -- 解析 / 参考答案
  score       DECIMAL(5,1) DEFAULT 0,     -- 试卷型分值
  difficulty  TINYINT DEFAULT 2,
  source      VARCHAR(64),                -- 来源，如 “2023 真题”
  sort        INT DEFAULT 0,
  status      TINYINT DEFAULT 1,
  INDEX idx_chapter (chapter_id, status, sort)
);
```

### 4.2 用户域

```sql
CREATE TABLE app_user (
  phone       VARCHAR(20) UNIQUE,         -- Web 端主登录凭证，也是跨端合并账号的依据
  password    VARCHAR(100),               -- BCrypt，可空（只用验证码登录时）
  openid      VARCHAR(64) UNIQUE,         -- 二期小程序
  unionid     VARCHAR(64),
  register_from TINYINT DEFAULT 1,        -- 1 Web 2 小程序
  nickname    VARCHAR(64),
  avatar      VARCHAR(255),
  status      TINYINT DEFAULT 1,
  last_login_at DATETIME
);

-- 答题明细（每次作答一条，用于统计和错题判断）
CREATE TABLE answer_record (
  user_id     BIGINT NOT NULL,
  question_id BIGINT NOT NULL,
  chapter_id  BIGINT NOT NULL,
  session_id  BIGINT,                     -- 所属练习 / 考试会话
  user_answer VARCHAR(500),
  is_correct  TINYINT,                    -- 主观题为自评结果
  cost_ms     INT,
  INDEX idx_user_q (user_id, question_id),
  INDEX idx_user_time (user_id, created_at)
);

-- 练习 / 考试会话（断点续做、模拟卷成绩）
CREATE TABLE practice_session (
  user_id     BIGINT NOT NULL,
  chapter_id  BIGINT NOT NULL,
  mode        TINYINT NOT NULL,           -- 1 练习 2 背题 3 考试 4 错题重练 5 收藏练习
  status      TINYINT DEFAULT 0,          -- 0 进行中 1 已完成
  current_index INT DEFAULT 0,
  correct_count INT DEFAULT 0,
  answered_count INT DEFAULT 0,
  score       DECIMAL(6,1),
  started_at  DATETIME,
  finished_at DATETIME,
  INDEX idx_user_chapter (user_id, chapter_id, status)
);

-- 章节进度汇总（列表页展示进度 / 正确率，避免实时聚合）
CREATE TABLE user_chapter_progress (
  user_id     BIGINT NOT NULL,
  chapter_id  BIGINT NOT NULL,
  done_count  INT DEFAULT 0,
  correct_count INT DEFAULT 0,
  UNIQUE KEY uk_user_chapter (user_id, chapter_id)
);

-- 收藏集
CREATE TABLE user_favorite (
  user_id     BIGINT NOT NULL,
  question_id BIGINT NOT NULL,
  module_id   BIGINT NOT NULL,            -- 冗余，便于分组
  bank_id     BIGINT NOT NULL,
  chapter_id  BIGINT NOT NULL,
  UNIQUE KEY uk_user_q (user_id, question_id),
  INDEX idx_user_module (user_id, module_id, created_at)
);

-- 错题集
CREATE TABLE user_wrong_question (
  user_id     BIGINT NOT NULL,
  question_id BIGINT NOT NULL,
  module_id   BIGINT NOT NULL,
  bank_id     BIGINT NOT NULL,
  chapter_id  BIGINT NOT NULL,
  wrong_count INT DEFAULT 1,
  right_streak INT DEFAULT 0,             -- 连续答对次数，达到阈值自动移出
  last_wrong_answer VARCHAR(500),
  last_wrong_at DATETIME,
  status      TINYINT DEFAULT 1,          -- 1 在错题集 0 已移出（保留历史）
  UNIQUE KEY uk_user_q (user_id, question_id),
  INDEX idx_user_module (user_id, module_id, status)
);

CREATE TABLE feedback (
  user_id     BIGINT,
  question_id BIGINT NULL,                -- 题目纠错时有值
  type        TINYINT,                    -- 1 题目纠错 2 意见建议
  content     VARCHAR(1000),
  images      JSON,
  status      TINYINT DEFAULT 0,          -- 0 待处理 1 已处理
  reply       VARCHAR(500)
);
```

### 4.3 运营 & 系统域

`banner`、`notice`、`sys_config`（key-value，如 `wrong.remove.streak=2`）、`sys_admin`、`sys_role`、`sys_menu`、`sys_admin_role`、`sys_role_menu`、`sys_oper_log`、`import_task`（导入任务状态 / 结果文件）。

### 4.4 错题 / 收藏核心规则

- **答错**：`user_wrong_question` upsert，`wrong_count + 1`，`right_streak = 0`，`status = 1`
- **在错题集中答对**：`right_streak + 1`，达到 `wrong.remove.streak` 时 `status = 0`
- **手动移出**：`status = 0`
- 背题模式不写错题、不写进度
- 题目下架后，收藏 / 错题列表中显示“该题已下架”，不物理删除用户数据

## 5. 接口设计

统一响应 `{ code, msg, data }`，分页 `{ list, total, pageNum, pageSize }`。

### 5.1 用户端 `/api/app`

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/auth/sms-code` | 发送短信验证码（图形验证码 / 滑块 + 手机号、IP 限流） |
| POST | `/auth/sms-login` | 手机号 + 验证码登录，未注册自动注册，返回 JWT |
| POST | `/auth/register`、`/auth/login` | 手机号 + 密码注册 / 登录（短信上线前兜底） |
| POST | `/auth/wx-login` | 【二期】小程序 `code` 换 openid；配合手机号快速验证绑定到已有账号 |
| PUT | `/user/profile` | 更新头像昵称 |
| GET | `/user/stats` | 做题统计、打卡天数 |
| GET | `/home` | Banner、公告、模块列表、继续练习 |
| GET | `/modules/{id}/banks` | 模块下题库列表（含用户进度） |
| GET | `/banks/{id}/courses` | 科目列表（科目型） |
| GET | `/banks/{id}/chapters?courseId=` | 章节 / 试卷列表（含进度） |
| POST | `/sessions` | 开始练习 `{chapterId, mode}`，返回 sessionId + 题目 id 列表（有未完成会话则返回续做位置） |
| GET | `/sessions/{id}/questions?ids=` | 分批拉题目详情（考试模式不返回答案） |
| POST | `/sessions/{id}/answers` | 提交单题答案（练习模式即时返回对错 + 解析） |
| PUT | `/sessions/{id}/progress` | 保存做到第几题（续做用） |
| POST | `/sessions/{id}/submit` | 交卷 / 结束，返回结果 |
| GET | `/sessions/{id}/result` | 结果页 |
| GET | `/favorites/groups` | 收藏分组统计（按模块 / 题库 / 章节） |
| GET | `/favorites?moduleId=&chapterId=` | 收藏列表 |
| POST / DELETE | `/favorites/{questionId}` | 收藏 / 取消 |
| GET | `/wrongs/groups` | 错题分组统计 |
| GET | `/wrongs?moduleId=&chapterId=` | 错题列表 |
| DELETE | `/wrongs/{questionId}` | 手动移出 |
| POST | `/wrongs/practice` | 发起错题重练会话（同理 `/favorites/practice`） |
| POST | `/feedback` | 纠错 / 反馈（每人每天最多 20 条） |
| GET | `/feedback/mine` | 我的反馈（含回复） |

### 5.2 管理端 `/api/admin`

| 资源 | 接口 |
|---|---|
| 认证 | `POST /auth/login`、`GET /auth/info`（含角色）、`PUT /auth/password`（改自己密码）、`POST /auth/logout` |
| 模块 | `GET/POST/PUT/DELETE /modules` |
| 题库 | `GET/POST/PUT/DELETE /banks`、`PUT /banks/{id}/status` |
| 科目 | `GET/POST/PUT/DELETE /courses`、`PUT /courses/sort` |
| 章节 | `GET /chapters/tree?bankId=`、`POST/PUT/DELETE /chapters`、`PUT /chapters/sort` |
| 题目 | `GET /questions`（按模块/题库/科目/章节/题型/状态/关键字分页）、`GET/POST/PUT/DELETE /questions`、`PUT /questions/batch-status`、`POST /questions/batch-move`、`POST /questions/batch-delete` |
| 导入导出 | `GET /questions/import-template`、`POST /questions/import`（同步导入，一次最多 2000 题，全有或全无，返回逐行错误）、`GET /questions/export` |
| 文件 | `POST /files/upload`（图片；开发期存本地，上线换 OSS/COS） |
| 目录树 | `GET /content-tree`（题库-科目-章节，级联选择用） |
| 用户 / 反馈 | `GET /app-users`、`PUT /app-users/{id}/status`、`GET /feedback`、`PUT /feedback/{id}`（录题员也可处理） |
| 运营 | `/banners`、`/notices`、`/configs` |
| 系统 | `/admins`（增删改、`PUT /admins/{id}/password` 重置密码）、`/roles`；`/menus`、`/oper-logs` 后续再做 |

**角色**：`super_admin`（全部权限）、`editor` 录题员（题库 / 科目 / 章节 / 题目，模块只读，不能管账号）。在 `WebConfig` 按路由统一鉴权。
| 统计 | `GET /dashboard` |

## 6. 工程结构

```
Lemon/
├── docs/                       # 规划、接口文档、导入模板
├── lemon-server/               # Spring Boot
│   └── src/main/java/com/lemon/
│       ├── common/             # 统一响应、异常、分页、工具
│       ├── config/             # Security、Redis、MyBatis-Plus、Swagger
│       ├── security/           # JWT 过滤器（app / admin 两套）
│       ├── module/
│       │   ├── content/        # module/bank/course/chapter/question
│       │   ├── practice/       # session/answer/progress
│       │   ├── favorite/
│       │   ├── wrong/
│       │   ├── user/
│       │   ├── operation/      # banner/notice/feedback/config
│       │   └── system/         # admin/role/menu/log
│       └── controller/
│           ├── app/            # /api/app/**
│           └── admin/          # /api/admin/**
├── lemon-admin/                # Vue3 + Element Plus
└── lemon-app/                  # uni-app：一期 build:h5 发布 Web，二期 build:mp-weixin
```

**后端关键选型**

- 鉴权：Sa-Token，app 与 admin 两套登录体系隔离（StpAppUtil / StpAdminUtil，token 存 Redis）
- 数据库迁移：Flyway，表结构纳入版本管理
- Excel：EasyExcel 导入导出
- 接口文档：springdoc-openapi（Knife4j UI）
- 缓存：Redis 缓存题库 / 章节树、题目详情（后台改动时主动失效）；做题提交直接写库
- 文件：腾讯云 COS / 阿里云 OSS

> 也可以直接基于 RuoYi-Vue-Plus 起步，后台的 RBAC、日志、代码生成器都现成，能省 1～2 周。

## 8. 备案与部署

### 8.1 备案（网站 + 小程序并行申请）

网站备案和小程序备案是**两条独立流程**，同一主体可以同时提交，互不阻塞：

| 项 | 网站（ICP 备案） | 小程序备案 |
|---|---|---|
| 在哪提交 | 服务器所在云厂商的备案系统（阿里云 / 腾讯云），需先买国内服务器 | 微信公众平台 → 小程序后台 → 备案 |
| 前置条件 | 已注册域名（实名认证完成）、国内云服务器 | 已注册小程序（建议企业主体，完成微信认证 300 元/年） |
| 材料 | 营业执照、负责人身份证、域名证书、人脸核验 | 同左 + 小程序名称、服务类目 |
| 周期 | 一般 1～3 周（各省管局不同） | 一般 1～3 周 |
| 结果 | 备案号，网站底部需展示并链接到 beian.miit.gov.cn | 小程序备案号，备案通过才能提审上线 |

注意事项：

- **主体信息两边保持一致**（同一营业执照、同一负责人），之后小程序的 request 合法域名就直接用已备案的网站域名，接口共用
- **名称**：网站名称尽量避开“培训”“教育机构”这类容易被要求补充前置审批材料的字眼，小程序名称与网站名称尽量一致，方便品牌统一
- 网站内容涉及在线教育，部分省份管局会问是否涉及“教育培训”，按“题目练习工具 / 学习信息服务”描述即可，不涉及收费培训、直播课
- 网站后续如要收费（付费题库），需另外评估是否办理 ICP 经营许可证（EDI / ICP 证），一期免费不涉及
- 网站备案通过后 30 日内到全国互联网安全管理服务平台做**公安备案**
- 小程序类目：教育 → 在线教育 / 教育信息服务（以审核要求为准）
- 短信验证码需要短信签名，签名审核要求网站已备案或提供营业执照；所以一期先做“手机号 + 密码”兜底，备案通过后切到短信登录

### 8.2 备案期间的开发与测试

备案没下来之前，国内服务器的 80/443 端口不能对外提供网站访问，开发不受影响：

- 本地开发 + 局域网测试（手机连同一 WiFi 访问电脑 IP）
- 需要外网演示时：用香港 / 海外服务器临时部署测试环境，或通过内网穿透，仅限内部使用
- 小程序二期开发阶段可用开发者工具勾选“不校验合法域名”联调

### 8.3 部署

- 服务器：国内一台 2C4G 起步（Docker Compose：server + MySQL + Redis + Nginx）
- 域名规划（一个备案域名下用子域名即可，无需再备案）：
  - `www.xxx.com` → 用户端 Web（H5）
  - `admin.xxx.com` → 管理系统
  - `api.xxx.com` → 后端接口（同时作为小程序 request 合法域名）
- 全站 HTTPS（小程序强制要求，Web 也应如此），证书用云厂商免费证书或 Let's Encrypt
- 题目内容需确认版权（自编或已授权），避免审核和侵权风险
- 数据备份：MySQL 每日全量备份到对象存储

## 9. 开发里程碑（一期 Web 约 7 周，1 后端 + 1 前端）

备案与开发并行，备案周期（1～3 周）被开发周期完全覆盖，不会卡上线。

| 阶段 | 周期 | 产出 | 备案线（并行） |
|---|---|---|---|
| M0 准备 | 0.5 周 | 原型 / UI、表结构定稿、仓库与环境搭建 | 买域名 + 国内服务器，注册小程序并认证，**同时提交网站备案和小程序备案** |
| M1 后端基础 + 内容管理 | 1.5 周 | 工程骨架、管理员登录 RBAC、模块 / 题库 / 科目 / 章节 / 题目 CRUD 接口 | 管局审核中 |
| M2 管理系统 | 1.5 周 | 管理系统全部页面、Excel 导入导出、文件上传 | 预计备案通过 → 做公安备案、申请短信签名 |
| M3 Web 用户端主流程 | 2 周 | 账号登录、首页、题库 / 科目 / 章节列表、做题页三种模式、结果页、PC 宽屏适配 | 短信签名通过后接入短信登录 |
| M4 收藏 & 错题 & 统计 | 1 周 | 收藏集、错题集、错题重练、我的统计、反馈 | — |
| M5 联调测试上线 | 0.5～1 周 | 联调、浏览器兼容测试（Chrome / Safari / 微信内置浏览器）、录入首批题目、**Web 正式上线** | 网站底部挂备案号 |

### 二期：小程序（约 2 周，Web 上线后启动）

| 内容 | 说明 |
|---|---|
| 编译适配 | `build:mp-weixin`，处理条件编译差异（登录、分享、存储） |
| 微信登录 | `/auth/wx-login` + 手机号快速验证，与 Web 账号按手机号合并 |
| 配置 | 合法域名配置为 `api.xxx.com`，隐私协议、用户协议 |
| 提审 | 小程序备案已在一期完成，直接提交审核发布 |

**后续可选**：付费解锁题库（需评估 ICP 证）、每日一练推送、排行榜、AI 解析、真题按年份组卷、学习计划。
